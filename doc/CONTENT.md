# Работа с контентом

Все тексты сайта лежат в `src/content/` и правятся без правки кода.
Источник требований к тону и структуре — `doc/ABOUT.md`.

---

## 1. Где какой текст

| Блок сайта                                             | Файл                                |
| ------------------------------------------------------ | ----------------------------------- |
| Имя, должность, город, адрес, контакты, реквизиты, SEO | `src/data/site.ts`                  |
| 1. Первый экран                                        | `src/content/sections/hero.md`      |
| 2. С чем можно прийти                                  | `src/content/sections/requests.md`  |
| 3. Обо мне                                             | `src/content/sections/about.md`     |
| 4. Образование и профессиональный путь                 | `src/content/sections/education.md` |
| 5. Как проходит психотерапия                           | `src/content/sections/process.md`   |
| 6. Формат и стоимость                                  | `src/content/sections/pricing.md`   |
| 7. Страхи и вопросы                                    | `src/content/sections/faq.md`       |
| 8. Познакомиться поближе                               | `src/content/sections/social.md`    |
| 9. Запись и способы связи                              | `src/content/sections/contact.md`   |
| 10. Финальный блок и документы                         | `src/content/sections/footer.md`    |
| Политика конфиденциальности                            | `src/content/legal/privacy.md`      |
| Согласие на обработку ПДн                              | `src/content/legal/consent.md`      |

Порядок блоков на странице задаёт поле `order`. Подпись в навигации шапки —
поле `nav` (если его нет, блок в меню не появляется). Якорь — поле `anchor`.

## 2. Синтаксис YAML во frontmatter

```yaml
kind: pricing # вид секции, определяет форму файла
order: 6 # позиция на странице
anchor: pricing # якорь для ссылки #pricing
nav: Стоимость # подпись в меню (необязательно)
```

Правила, без которых сборка упадёт:

- строка с `: ` (двоеточие и пробел) берётся в кавычки:
  `note: 'Темы: психология отношений'`;
- многострочный текст — `>-` (переносы склеиваются в пробелы);
- `price` — число, не строка: `price: 2500`. Формат «2 500 ₽» подставляет код;
- `src` фотографии — только имя файла из `src/assets/photos/`;
- `alt` обязателен: он остаётся в вёрстке, даже если фотография заменится.

Забытое обязательное поле останавливает `npm run build` сообщением вида
`sections → pricing data does not match collection schema` с указанием файла
и поля. Это лучше, чем молчаливая поломка страницы.

## 3. Тон

Сайт пишет человек, который помогает разобраться, а не человек, который знает,
как правильно жить.

Обязательно:

- спокойно и по-человечески, без давления и спешки;
- без обещаний результата и сроков («изменим жизнь за три сессии»);
- без диагнозов, медицинских обещаний и «лечения»;
- без давления на запись: «можно прийти, можно не приходить»;
- без профессионального жаргона там, где можно сказать обычными словами;
- с уважением к сомнениям: «а точно ли мне нужен психолог», «а вдруг будут оценивать».

Недопустимо:

- манипулятивные формулировки и искусственный дефицит мест;
- обещания «изменим жизнь», «избавим от тревоги навсегда»;
- формальные резюме вместо живого текста;
- конструкции вида «потерял(а)» в самых читаемых местах — лучше нейтральная формулировка.

Оформление: «ёлочки», тире «—», неразрывные пробелы в устойчивых оборотах,
короткие абзацы. Читатель приходит растерянным — текст должен снимать напряжение,
а не добавлять его.

## 4. Формулировки-подсказки

Готовые формулировки есть в `doc/ABOUT.md` (раздел 6, блоки 2, 5, 7) —
это согласованный тон, от него можно отталкиваться при правках.

Секция «С чем можно прийти» строится на узнавании, а не на перечне услуг:
фразы пишутся от первого лица, коротко, без терминов.
Цепочка страницы: «я узнаю себя» → «я понимаю, кто это» → «я понимаю, как
работает» → «я понимаю, сколько стоит» → «я выбираю способ связи».

## 5. Форма записи

Форма ничего не отправляет на сервер: она собирает текст и открывает выбранный
мессенджер. Прямые ссылки на мессенджеры работают и без JavaScript.

Шаблон сообщения — поле `messageTemplate` в `contact.md`, подстановки:
`{name}`, `{contact}`, `{message}`.

Если понадобится приём заявок на почту — это не требует сервера: достаточно
добавить в `methods` мессенджер `email` (ссылка `mailto:` уже поддерживается
в `src/lib/links.ts`).

## 7. Проверка после правки текста

```bash
npm run build
```

Сборка валидирует схему и рендерит страницу. Затем откройте `npm run preview`
и пройдите страницу до конца: длинный текст не должен ломать сетку, а
аккордеон FAQ — открываться по клику.
