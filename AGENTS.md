# AGENTS.md

Инструкции для ИИ-агентов и для человека, который работает с этим репозиторием.
Короткая версия: **тексты лежат в `src/content/`, всё остальное трогать не нужно.**

---

## 1. Что это за проект

Одностраничный лендинг психотерапевта (гештальт-подход). Статическая сборка,
публикуется в GitHub Pages. Исходное техническое задание — `doc/ABOUT.md`,
его требования обязательны (тон текстов, структура блоков, юридические документы).

Аудитория: взрослые люди в состоянии тревоги, растерянности, кризиса в отношениях.
Задача сайта — чтобы человек узнал себя в текстах и записался на первую сессию.

## 2. Стек

| Что           | Чем                                                       | Версия           |
| ------------- | --------------------------------------------------------- | ---------------- |
| Сборка        | Astro (static output)                                     | ^7.3             |
| Стили         | Tailwind CSS v4 + Vite-плагин, тема в CSS                 | ^4.3             |
| Шрифты        | Onest (текст) + Playfair Display (заголовки), self-hosted | ^5.3             |
| Контент       | Content Collections + Zod                                 | встроено в Astro |
| Клиентский JS | без фреймворков, нативные модули                          | —                |
| Проверки      | `astro check`, ESLint 10, Prettier 3                      | —                |
| Публикация    | GitHub Actions → GitHub Pages                             | —                |
| Контейнер     | Containerfile (podman/docker) + Caddy                     | —                |

Пакетный менеджер — **npm** (не pnpm: локальный corepack несовместим с pnpm 12).

## 3. Команды

```bash
npm install          # зависимости
npm run dev          # http://localhost:4321
npm run build        # сборка + OG-картинка + предзагрузка шрифтов → dist/
npm run preview      # локальный просмотр собранного dist/
npm run check        # astro check: типы .astro и .ts
npm run lint         # eslint
npm run format       # prettier --write
npm run verify       # check + lint + format:check — перед коммитом

# Контейнер
./scripts/container.sh build   # собрать образ
./scripts/container.sh run     # собрать и запустить локально
./scripts/container.sh check   # проверить, что в образе есть сайт
./scripts/container.sh push    # отправить образ в GitHub Packages
podman-compose up -d           # запуск на сервере из compose.yaml
```

**Правило: текст не хардкодится в разметку.** Если нужно поменять формулировку —
правится markdown. Если правка требует изменения структуры — сначала схема в
`src/schemas/sections.ts`, потом разметка, потом контент.

### Правила YAML во frontmatter

- Строки, содержащие `: ` (двоеточие с пробелом), берутся в кавычки:
  `note: 'Темы: психология отношений'`. Без кавычек YAML сделает из строки объект
  и сборка упадёт с понятной ошибкой.
- Многострочные тексты — через `>-` (схлопывает переносы в пробелы).
- Числа остаются числами: `price: 2500`. Формат выводится через `Intl`.

### Схемы — единственный источник правды

`src/schemas/sections.ts` — `z.discriminatedUnion('kind', [...])` по десяти видам
секций. `src/schemas/site.ts` — глобальные данные. `src/schemas/legal.ts` — юр. страницы.

Схема проверяется на сборке: забытое поле останавливает `npm run build` с
указанием файла и имени поля. **Это единственная точка отказа, которую нужно
использовать вместо молчаливых заглушек.**

## 5. Как добавить новую секцию

1. Добавить вид в `src/schemas/sections.ts`.
2. Создать `src/components/sections/<Kind>.astro`, принимающий `{ data, entry }`.
3. Зарегистрировать в `src/components/sections/index.ts` (явная карта).
4. Создать `src/content/sections/<kind>.md` с `kind`, `order`, `anchor`.
5. `npm run verify && npm run build`.

Неизвестный `kind` приводит к ошибке сборки — это намеренно.

## 6. Дизайн-система

Токены — только в `src/styles/tokens.css`, цвета заданы в **OKLCH**.
Компонентные классы (`.btn`, `.card`, `.eyebrow`, `.page`, `.section`, `.chip`)
живут в `src/styles/global.css`, продольный текст — в `src/styles/prose.css`.

Шкала: `cream` (тёплая молочная база) → `mist` (светло-голубые блоки) →
`clay` (пыльно-розовый, терракотовый акцент) → `ink` (текст).

Правила, которые нельзя нарушать:

- Контраст текста ≥ 4.5:1. Терракотовая кнопка — `clay-700`, не `clay-500`.
- Тёмная тема не используется: палитра тёплая и требует света.
- Никаких стоковых фото, «неоновых» градиентов и «стеклянных» карточек.
- Мотив бренда — «фигура и фон»: две соприкасающиеся формы
  (`src/components/ui/FigureGround.astro`). Он же используется как заглушка
  вместо фотографии.
- Анимации — только плавные и медленные (`--ease-soft`), без «отскоков».
  Всё, что анимируется, обязано иметь статичное состояние при
  `prefers-reduced-motion: reduce`.

Типографика: Playfair Display — только заголовки, Onest — всё остальное.
Жирный шрифт в текстах не используется для смыслового выделения.

## 7. Тон текстов

Обязательные ограничения (из `doc/ABOUT.md`):

- спокойно, по-человечески, без давления и манипуляций;
- без обещаний результата («изменим жизнь за три сессии» — нельзя);
- без диагнозов и медицинских обещаний;
- не «эксперт сверху»: специалист помогает разобраться, а не учит жить;
- «ё» по правилам, тире — «—», кавычки — «»;
- «Мужчина или женщина» — нейтральные формулировки, без «(а)» в тексте,
  который читают чаще всего.

## 8. Доступность (обязательно, WCAG 2.2 AA)

- Содержимое читается без JavaScript: появления — через класс `.reveal`,
  который снимает `html.no-js`; форма записи скрыта без JS (`data-js-only`),
  рядом есть рабочие прямые ссылки на мессенджеры.
- Аккордеон FAQ собран по WAI-ARIA APG: `aria-expanded`, `aria-controls`,
  панели с `role="region"`.
- У каждой секции заголовок и `aria-labelledby`; декоративные элементы —
  `aria-hidden` и без ролей.
- Пропуск ссылки «Перейти к содержанию», видимый фокус, работа с клавиатуры.
- Перед завершением задачи прогонять axe (см. раздел «Приёмка»).

## 9. Производительность и приватность

- Клиентский JS — четыре маленьких модуля, без фреймворков и аналитики.
- Шрифты, стили и картинки — с домена сайта, внешних запросов нет.
- Форма ничего не отправляет на сервер: собирает текст и открывает мессенджер
  пользователя. Это осознанное решение, а не временная заглушка.
- Cookie и счётчики не используются. Если добавляются — обновить
  раздел 7 политики конфиденциальности и добавить баннер согласия.

## 10. Чего делать нельзя

- Не хардкодить тексты в `.astro`-компонентах.
- Не добавлять зависимости без согласования с владельцем проекта: на каждый
  пакет приходится аргумент «зачем именно он здесь».
- Не менять цвет напрямую в разметке: только токены.
- Не оставлять вымышленные имя, телефон, реквизиты или даты в контенте —
  они помечены `TODO`.
- Не удалять `public/_headers`. Не заменять `src/pages/robots.txt.ts` на
  статический файл: адрес карты сайта должен совпадать с публикацией.
- Не писать абсолютные пути вида `/favicon.svg` в разметке: при публикации
  на подпути они перестанут работать. Использовать `import.meta.env.BASE_URL`.
- Не коммитить `dist/`, `public/og.png`, `node_modules/`.

## 11. Контейнер

Сайт статический, поэтому в образе нет ни Node, ни сборщика: только Caddy
и готовые файлы. Сборка двухэтапная — `Containerfile`.

```bash
./scripts/container.sh build   # локальный образ
./scripts/container.sh run     # запуск на :8080
./scripts/container.sh check   # проверка содержимого образа
```

Правила, которые нельзя нарушать:

- **Caddy слушает непривилегированные 8080 и 8443.** Иначе контейнер не
  запустится под rootless podman без изменения sysctl. На хосте порты
  пробрасываются 80→8080 и 443→8443.
- **`ACME_EMAIL` не задавать пустой строкой.** Caddy подставляет значение
  по умолчанию только для незаданной переменной, а пустая строка валит
  конфигурацию. В `compose.yaml` переменная закомментирована.
- **Сертификаты лежат в volume `/data`.** Без volume Caddy выпускал бы
  новый сертификат при каждом пересоздании и упёрся бы в лимиты
  Let's Encrypt.
- **Матчеры в Caddyfile объявляются на уровне сайта**, а не внутри блока
  `header`. Форма `поле { <матчер> <значение> }` внутри `header` не
  поддерживается и создаёт мусорные заголовки вместо правил кеширования.
- **Заголовки безопасности продублированы** в `deploy/caddy/Caddyfile` и
  в `public/_headers`: первый нужен контейнеру, второй — GitHub Pages.
  Правки в оба файла.

Полная инструкция по развёртыванию, портам и диагностике — `doc/DEPLOY.md`.

## 12. Деплой

`master` → GitHub Actions → GitHub Pages (`.github/workflows/deploy.yml`).
Перед сборкой прогоняются `astro check` и сама сборка.

Workflow сам вычисляет адрес и базовый путь: для сайта проекта это
`https://<владелец>.github.io/<репозиторий>` с базой `/<репозиторий>`,
для собственного домена — `https://<домен>` с базой `/`. Ошибка в базовом
пути даёт «голый» сайт без стилей, поэтому вручную эти значения задавать
не нужно.

Единственная ручная настройка — переменная репозитория
(Settings → Secrets and variables → Actions → **Variables**):

| Переменная      | По умолчанию | Назначение                            |
| --------------- | ------------ | ------------------------------------- |
| `CUSTOM_DOMAIN` | —            | Домен сайта, например `psy.yainna.ru` |

Как только домен направлен на GitHub Pages и переменная задана, следующий
деплой соберёт сайт под него и добавит `CNAME` в артефакт. Пока переменная
пустая, сайт работает по адресу `itmagelab.github.io/psy.yainna.ru`.

## 13. Приёмка перед коммитом

```bash

npm run build    # сборка должна быть зелёной
```

После изменения вёрстки — открыть `npm run preview` и проверить на 390px
и 1440px: порядок блоков, отсутствие горизонтальной прокрутки, контраст.

Если менялись `Containerfile`, `deploy/caddy/Caddyfile` или `compose.yaml`:

```bash
./scripts/container.sh run     # и проверить curl -I http://localhost:8080/
```
